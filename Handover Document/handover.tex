\section{Project Overview}
% ════════════════════════════════════════════════════════════

\textbf{BUDGT} is a sleek, privacy-focused, and high-performance personal finance tracking application designed with a mobile-first philosophy. It is available across three platforms:

\begin{itemize}[leftmargin=1.5em]
  \item \textbf{Android Native App} --- a Kotlin/WebView shell wrapping the bundled web engine, distributed as a debug APK (\texttt{Budgt.apk}, Version 1.0.6, versionCode~7).
  \item \textbf{iOS Native App} --- a pure SwiftUI application targeting iOS 16/17+, opened and built via Xcode.
  \item \textbf{Progressive Web App (PWA)} --- a Vanilla JavaScript Single-Page Application (SPA) built with Vite 8, installable from any modern browser.
\end{itemize}

All financial data is stored \textbf{100\% client-side}. There is no remote backend, no cloud database, and no external analytics. User data never leaves the device.

\subsection{Core Feature Set}

\begin{longtable}{L{4.5cm} L{10cm}}
  \toprule
  \textbf{Feature} & \textbf{Description} \\
  \midrule
  \endhead
  Real-Time Dashboard & Net worth overview, monthly cash flow (income vs.\ expense), category spending charts, and a quick transaction feed. \\[4pt]
  Multi-Account Ledger & Supports Asset accounts (Bank, Cash, Savings) and Liability accounts (Credit Card, Loans). Comprehensive logging of Withdrawals, Deposits, and Transfers with auto-reconciliation. \\[4pt]
  Budget Limits & Category-level monthly spending caps with visual progress bars and threshold warnings. \\[4pt]
  Piggy Banks & Dedicated savings goal tracker with target amounts, progress milestones, and linked accounts. \\[4pt]
  Scheduled Bills & Recurring bill tracker with due-date monitoring, auto-pay flags, and payment history. \\[4pt]
  Financial Reports & In-browser Profit \& Loss (P\&L) PDF export, Excel/CSV ledger dump, and full JSON backup/restore. \\[4pt]
  Internationalization & Multi-currency (USD, IDR, MYR, EUR, GBP, JPY, etc.) with regional number formatting; multi-language (English, Indonesian, Malay). \\[4pt]
  PWA / Offline & Service Worker caches all assets; app is installable to the home screen and runs without internet. \\
  \bottomrule
\end{longtable}

\section{System Architecture}
% ════════════════════════════════════════════════════════════

\subsection{Client-Side Storage Architecture}

BUDGT does \textbf{not} use a remote server database. All data is stored in the browser's \texttt{localStorage} (Web/Android) or \texttt{UserDefaults} (iOS). The web engine uses a three-tier architecture:

\begin{enumerate}[leftmargin=1.5em]
  \item \textbf{UI Layer} (Views) --- Renders data and dispatches user actions.
  \item \textbf{Reactive State Layer} (\texttt{state.js}) --- Manages an in-memory state cache, performs balance calculations, and emits change events via a Pub/Sub pattern.
  \item \textbf{Persistence Layer} (\texttt{store.js}) --- Serializes/deserializes JSON objects to/from \texttt{localStorage} with the \texttt{budgt\_} key prefix.
\end{enumerate}

\subsection{localStorage Data Collections}

\begin{longtable}{L{3.8cm} L{10.7cm}}
  \toprule
  \textbf{Key} & \textbf{Schema \& Description} \\
  \midrule
  \endhead
  \texttt{budgt\_transactions} & Array of transaction records: \texttt{\{id, type, amount, description, categoryId, sourceAccountId, destAccountId, date, notes, tags, createdAt\}}. \texttt{type} is one of \texttt{withdrawal | deposit | transfer}. \\[4pt]
  \texttt{budgt\_accounts} & Array of financial accounts: \texttt{\{id, name, type, balance, currency, icon, color, createdAt\}}. \texttt{type} is one of \texttt{asset | liability}. \\[4pt]
  \texttt{budgt\_categories} & Expense/income categories: \texttt{\{id, name, icon, color, type\}}. \texttt{type} is \texttt{expense | income}. \\[4pt]
  \texttt{budgt\_budgets} & Category spending caps: \texttt{\{id, categoryId, amount, period, startDate\}}. \\[4pt]
  \texttt{budgt\_piggybanks} & Savings goals: \texttt{\{id, name, targetAmount, currentAmount, icon, targetDate, accountId\}}. \\[4pt]
  \texttt{budgt\_bills} & Recurring bills: \texttt{\{id, name, amount, categoryId, frequency, nextDueDate, autoPay, lastPaidDate\}}. \\[4pt]
  \texttt{budgt\_settings} & User preferences: \texttt{\{currency, locale, currencySymbol\}}. \\[4pt]
  \texttt{budgt\_seeded} & Boolean flag --- prevents re-seeding demo data on subsequent app launches. \\
  \bottomrule
\end{longtable}

\subsection{Automatic Balance Reconciliation}

When a transaction is created or deleted, the following sequence is triggered automatically:

\begin{enumerate}[leftmargin=1.5em]
  \item \texttt{State.addTransaction(tx)} writes the record to \texttt{budgt\_transactions}.
  \item \texttt{\_applyTransactionToAccounts()} updates the corresponding \texttt{balance} field in \texttt{budgt\_accounts}.
  \item Events \texttt{emit('transactions')} and \texttt{emit('accounts')} notify all UI subscribers to re-render immediately.
\end{enumerate}

\subsection{Android Native Bridge}

The Android shell exposes a JavaScript interface called \texttt{AndroidBridge} that enables the web engine to interact with native Android features:

\begin{itemize}[leftmargin=1.5em]
  \item \textbf{\texttt{setTheme(isDark: Boolean)}} --- Synchronizes the native status bar and navigation bar colours with the web app's active dark/light theme.
  \item \textbf{\texttt{downloadFile(base64Data, fileName, mimeType)}} --- Saves in-browser generated files (PDFs, Excel sheets) to the device's \texttt{Downloads} directory using \texttt{MediaStore} (Android 10+) or legacy file I/O.
\end{itemize}

Assets are served via \texttt{WebViewAssetLoader} over the \texttt{https://appassets.androidplatform.net/} pseudo-domain, bypassing file:// restrictions and enabling \texttt{localStorage} access.

\section{Data Management}
% ════════════════════════════════════════════════════════════

\subsection{Seed \& Reset}

On the very first launch of the web/Android app, \texttt{seedData()} in \texttt{seed.js} runs automatically and populates:
\begin{itemize}[leftmargin=1.5em]
  \item 12 default categories (10 expense, 2 income)
  \item 3 default accounts (Checking, Savings, Cash) with demo balances
  \item 14 demo transactions for the current month
  \item 5 default budgets, 3 piggy banks, and 4 recurring bills
  \item Default settings: \texttt{USD / en-US}
\end{itemize}

A boolean flag \texttt{budgt\_seeded} is set to \texttt{true} afterwards to prevent re-seeding. Calling \texttt{resetToZero()} clears all transaction/budget/bill data while preserving category definitions and resetting account balances to zero.

\subsection{Backup \& Restore}

Users can export all data as a \textbf{JSON file} via \textbf{Settings $\rightarrow$ Backup \& Restore}. The JSON file can be re-imported into any browser or Android device to fully restore the dataset. This is the primary data migration mechanism between devices.

\subsection{Upgrading to Cloud Sync (Future)}

Because all storage logic is isolated inside \texttt{store.js}, connecting to a cloud backend (e.g.\ \textbf{Supabase} or \textbf{Firebase}) requires only:
\begin{enumerate}[leftmargin=1.5em]
  \item Replacing \texttt{localStorage} read/write calls inside \texttt{store.js} with remote API calls.
  \item Adding an authentication layer (OAuth or email/password) so data is user-scoped.
\end{enumerate}
No changes to the UI views or state manager are needed.

\section{Deployment \& Distribution}
% ════════════════════════════════════════════════════════════

\subsection{Web App (PWA)}

\begin{enumerate}[leftmargin=1.5em]
  \item Run \texttt{npm run build} in \texttt{budgt-app/} to produce the \texttt{dist/} folder.
  \item Deploy the \texttt{dist/} folder to any static web hosting service (Netlify, Vercel, GitHub Pages, Firebase Hosting, etc.).
  \item The Service Worker (\texttt{sw.js}) will automatically cache assets for offline use after the first load.
  \item Users may install the PWA to their home screen via the browser's ``Add to Home Screen'' prompt.
\end{enumerate}

\subsection{Android APK}

\begin{enumerate}[leftmargin=1.5em]
  \item Ensure the bundled web assets in \texttt{Budgt-mobile/app/src/main/assets/} reflect the latest \texttt{dist/} build.
  \item Run \texttt{.\textbackslash{}gradlew.bat assembleDebug} (debug) or \texttt{assembleRelease} (signed release) from the \texttt{Budgt-mobile/} directory.
  \item Distribute the APK directly (sideload) or upload to Google Play Console.
  \item The current released APK is \textbf{Version 1.0.6 (versionCode 7)}.
\end{enumerate}

\begin{cautionbox}
The current APK is a \textbf{debug build}. For Play Store submission, a \textbf{signed release APK or AAB} must be produced with a keystore. Ensure the keystore file and credentials are stored securely and backed up --- losing the keystore means the app cannot be updated on the Play Store.
\end{cautionbox}

\subsection{iOS (Xcode / TestFlight / App Store)}

\begin{enumerate}[leftmargin=1.5em]
  \item Open \texttt{Budgt.xcodeproj} in Xcode on macOS.
  \item Set the correct \textbf{Team} and \textbf{Bundle Identifier} in the project target settings.
  \item Archive the app: \textbf{Product $\rightarrow$ Archive}.
  \item Distribute via \textbf{TestFlight} (internal testing) or \textbf{App Store Connect} (public release).
\end{enumerate}

\section{Known Issues \& Limitations}

\begin{longtable}{L{3cm} C{2cm} L{9.5cm}}
  \toprule
  \textbf{Issue} & \textbf{Severity} & \textbf{Details} \\
  \midrule
  \endhead
  localStorage Limit & Medium & Browsers impose a $\sim$5--10 MB limit on \texttt{localStorage}. Users with very high transaction volumes (thousands of records) may encounter storage quota errors. Mitigation: periodic JSON export/archival. \\[4pt]
  No Multi-Device Sync & Medium & Data exists only on the device where it was entered. A JSON backup/restore workflow is the only cross-device migration path. \\[4pt]
  Debug APK & High & The distributed Android APK is a debug build; it should not be submitted to the Play Store without a signed release build. \\[4pt]
  JVM Crash Logs & Low & Multiple \texttt{hs\_err\_pidXXXX.log} and \texttt{replay\_pidXXXX.log} JVM crash logs are present in the \texttt{Budgt-mobile/} root directory. These are artifacts from Android Studio crashes and can be safely deleted. \\[4pt]
  iOS Data Isolation & Info & The iOS app uses \texttt{UserDefaults} and is entirely independent of the web/Android data --- there is no shared storage between platforms. \\[4pt]
  No Authentication & Info & There is no user login or authentication mechanism. All data is local and accessible to anyone with physical access to the device. \\
  \bottomrule
\end{longtable}

\section{Future Roadmap Considerations}
% ════════════════════════════════════════════════════════════

The following enhancements were identified during development but have not yet been implemented:

\begin{itemize}[leftmargin=1.5em, itemsep=4pt]
  \item \textbf{Cloud Sync / Multi-Device Support} --- Integrate a backend (Supabase, Firebase) to sync data across devices. The \texttt{store.js} abstraction layer is already designed to facilitate this with minimal refactoring.
  \item \textbf{User Authentication} --- Add OAuth (Google/Apple Sign-In) or email/password login to scope data per user for multi-device sync.
  \item \textbf{Recurring Transaction Automation} --- Auto-generate transaction records from the Bills/Subscriptions list when due dates are reached.
  \item \textbf{Signed Release APK / Play Store Listing} --- Convert the debug APK to a signed release build and submit to Google Play.
  \item \textbf{iOS App Store Submission} --- Submit the SwiftUI app to the Apple App Store with a proper provisioning profile.
  \item \textbf{Investment Tracking} --- Add a module for tracking stocks, crypto, and other investment portfolios within the net worth calculation.
  \item \textbf{Debt Payoff Planner} --- Visual planner for liability accounts with payoff projections (avalanche/snowball methods).
  \item \textbf{Localization Expansion} --- Extend multi-language support beyond English, Indonesian, and Malay (e.g.\ Chinese, Arabic).
  \item \textbf{Accessibility (a11y)} --- Audit and improve ARIA labels, keyboard navigation, and contrast ratios across the web UI.
\end{itemize}
